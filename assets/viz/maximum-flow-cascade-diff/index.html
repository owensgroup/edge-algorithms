Max-flow: the three cascades, side by side

Push–relabel written as Extended Einsums — bulk-synchronous, then sequentialised two different ways.

All three compute the same maximum flow on the same graph. The highlighting is computed by diffing the specs, not marked by hand.

Column 2 — predicated. The parallel cascade with one Einsum added and two changed. Every other line is identical, character for character. This is the source of the claim that parallelism here is one Einsum — and it is true, as far as it goes.

Column 3 — branching. What you get writing the pseudocode out directly: pick one vertex, test it once, then push or relabel. It has to move the admissibility test before the push and drop the three post-push recomputations — which the parallel cascade needs (bulk-synchronous execution has no read-after-write) and a sequential one does not. Column 2 keeps them, and that is why a vertex there can push and relabel in the same round: 26 rounds for 29 operations. Column 3 is 29 rounds, 29 operations, the same 29 the textbook performs, in the same order.

Reading column 3. Its rows are aligned to column 2 so the expressions line up, which means its own labels run out of order — B11 and B12 appear down in the relabel section because that is where the predicated cascade asks the same question. That is the move, made visible: in the branching cascade they run before the push, right after B10.
